## ADR-004 — Stockage des credentials via GNOME Keyring

**Contexte :** Les exigences ENF-4 et ENF-5 imposent que les identifiants
Garmin Connect ne soient jamais écrits en clair dans les logs ou le code
source, et qu'ils soient stockés localement de manière sécurisée
(chiffrement ou mécanisme système). Le spike S-2 utilisait un fichier
`credentials.env` avec `chmod 600` pour la simplicité du prototypage.
L'application finale doit adopter une solution plus robuste. Le persona
utilise Fedora 44 / GNOME, qui fournit un service de trousseau natif.

**Décision :** GNOME Keyring via `secretstorage` (bindings Python pour
libsecret / DBus Secret Service API).

Fonctionnement :
- Les credentials (email, mot de passe) sont stockés dans le trousseau
  GNOME, déverrouillé automatiquement à l'ouverture de session utilisateur.
- L'application utilise `secretstorage` pour créer/lire/supprimer une
  entrée dans la collection `login` du keyring.
- Le tokenstore (`tokens.json`) reste dans `~/.config/openrunner55/`
  (chmod 600, dossier chmod 700) car les tokens ont une courte durée de
  vie (~1 jour) et sont rafraîchis automatiquement. Ils ne contiennent
  pas le mot de passe.
- Au lancement, l'application tente d'abord `resume_session()` depuis le
  tokenstore. Si le token est expiré et le refresh échoue → lecture des
  credentials dans le keyring → login fresh → nouveau tokenstore.
- L'utilisateur peut supprimer ou mettre à jour les credentials depuis
  l'interface (US-1.3).

**Alternatives écartées :**

| Alternative | Raison du rejet |
|------------|-----------------|
| **Fichier `.env` chmod 600** (spike) | Stockage en clair sur disque. Un accès lecture au fichier compromet les identifiants. Ne répond pas à ENF-5. |
| **Fichier chiffré avec `cryptography`** | Gestion de clé de chiffrement complexe (où stocker la clé ?). Réinvente un keyring. Jamais aussi sûr que le mécanisme système. |
| **Bibliothèque `keyring`** (wrapper Python générique) | Fonctionne, mais `secretstorage` est le backend natif sous GNOME. `keyring` ajoute une abstraction inutile puisqu'on cible exclusivement GNOME. |
| **Variable d'environnement** | Non persistant, non sécurisé (visible dans `/proc`), ne répond pas à EF-2. |

**Conséquences :**

- **Dépendance `secretstorage`** : paquet Python installable via pip. Backend
  DBus/libsecret présent par défaut sur Fedora/GNOME. Pas de dépendance
  système supplémentaire.
- **Portabilité limitée à GNOME/KDE** : `secretstorage` utilise le service
  DBus Secret Service, standard freedesktop.org. Fonctionne sous GNOME
  (gnome-keyring) et KDE (ksecretservice). Pas de support Windows/macOS —
  hors périmètre.
- **Sécurité :** les credentials sont chiffrés au repos par le keyring
  GNOME. L'application n'a jamais accès au mot de passe en dehors du
  processus de login (pas de cache persistant).
- **Tokenstore distinct :** la séparation credentials (keyring) / tokens
  (fichier) est intentionnelle. Les tokens expirent en ~1 jour et sont
  regénérés automatiquement. Les credentials ne sont sollicités que si le
  refresh token lui-même échoue.
- **Interface `auth/keyring_store.py` :** module dédié avec les méthodes
  `save(email, password)`, `load() -> (email, password)`, `delete()`.
  L'authenticator appelle ce module, le reste du code ignore l'existence
  du keyring.

- **Non-support du MFA (risque résiduel accepté) :** l'authentification
  multi-facteurs (MFA) n'est pas implémentée dans le MVP. La bibliothèque
  `garminconnect` supporte le MFA via un callback `prompt_mfa`, mais le
  développeur n'utilise pas le MFA sur son compte Garmin et ne souhaite
  pas développer ce parcours. Si un utilisateur ayant activé le MFA tente
  de se connecter, l'authentification échouera avec un message explicite
  dans l'UI : « L'authentification multi-facteurs (MFA) n'est pas supportée.
  Désactivez-la temporairement dans vos paramètres Garmin Connect pour
  utiliser OpenRunner55. » Le support du MFA pourra être ajouté dans une
  version ultérieure si le besoin émerge.

**Références :** EF-2, EF-3, ENF-4, ENF-5. ADR-002 pour le module `auth/`.
