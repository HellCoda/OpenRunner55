## ADR-009 — Packaging et distribution (AppImage)

**Contexte :** Le projet est personnel mais sera publié sur GitHub. Le
persona utilise Fedora 44 / GNOME. ADR-003 a tranché GTK 4 + libadwaita,
mais aucun ADR ne définit comment installer et distribuer l'application.
L'application doit pouvoir être exécutée en mode développement (depuis le
dépôt) et distribuée sous forme d'un exécutable autonome.

**Décision :** Distribution via **AppImage** (exécutable unique). Pas de
Flatpak, pas de RPM/dnf. En développement, exécution directe depuis le dépôt.

---

### Deux modes d'exécution

| Mode | Commande | Cible | Dépendances |
|------|----------|-------|-------------|
| **Développement** | `python -m openrunner55` | Développeur, depuis le dépôt | Python 3.12+, `pip install -e .`, paquets système (GTK4, libadwaita via dnf) |
| **Distribution** | `./OpenRunner55-x86_64.AppImage` | Utilisateur final (GitHub Releases) | Aucune — tout est embarqué |

---

### pyproject.toml

```toml
[project]
name = "openrunner55"
version = "0.1.0"
description = "Sync Garmin Connect ↔ Forerunner 55 via USB"
requires-python = ">=3.12"
dependencies = [
    "garminconnect>=0.2.30",
    "garmin-fit-sdk>=2.0.0",
    "curl_cffi>=0.7.0",
    "pydantic>=2.0.0",
    "secretstorage>=3.0.0",
    "pyudev>=0.24.0",
]

[project.scripts]
openrunner55 = "openrunner55.main:main"

[build-system]
requires = ["setuptools>=75.0"]
build-backend = "setuptools.build_meta"
```

**Note sur PyGObject :** `pygobject` (bindings GTK) **n'est pas listé** dans
`dependencies` car il ne s'installe pas via pip — il est fourni par le
système (`python3-gobject`, `gtk4`, `libadwaita` via dnf). Un `README.md`
documentera les prérequis système pour le mode développement.

### Build de l'AppImage

Le script `scripts/build-appimage.sh` produit un fichier unique
`OpenRunner55-x86_64.AppImage` :

1. **Préparation :** création d'un répertoire `AppDir/` avec la structure AppDir
   standard (AppRun, .desktop, icône, usr/bin, usr/lib)
2. **Runtime Python :** environnement virtuel Python 3.12+ bundlé dans
   `AppDir/usr/python/` avec toutes les dépendances pip installées
3. **Bibliothèques système :** copie de GTK4, libadwaita, libsecret, libudev
   et de leurs dépendances transitives dans `AppDir/usr/lib/`
4. **Code applicatif :** le package `openrunner55/` est installé dans
   l'environnement virtuel (`pip install .`)
5. **AppRun :** script shell minimal qui configure `LD_LIBRARY_PATH`,
   `GI_TYPELIB_PATH`, `PYTHONPATH` et lance `python -m openrunner55`
6. **Empaquetage :** `linuxdeploy` ou `appimagetool` compresse AppDir en
   AppImage

**Outil recommandé :** `appimagetool` (binaire statique officiel, sans
dépendances). Alternative : `python-appimage` si `appimagetool` s'avère
trop complexe pour bundler GTK.

**Contrainte :** l'AppImage produite est testée sur Fedora 44 / GNOME.
La compatibilité avec d'autres distributions n'est pas garantie (mais
probable sur toute distrib Linux récente avec glibc ≥ 2.35).

### Icône et intégration bureau

Fichier `assets/openrunner55.desktop` :

```desktop
[Desktop Entry]
Type=Application
Name=OpenRunner55
Comment=Synchronisation Garmin Connect ↔ Forerunner 55
Icon=openrunner55
Exec=openrunner55
Categories=Utility;Sports;
Terminal=false
```

L'AppImage intègre ce fichier (standard AppDir). Pas d'intégration dans le
menu GNOME via `xdg-desktop-menu` — l'utilisateur lance l'AppImage
directement ou l'intègre manuellement.

### Alternatives écartées

| Alternative | Raison du rejet |
|------------|-----------------|
| **Flatpak** | Complexité du manifeste, sandbox contraignante pour l'accès USB (udev, montage), build infrastructure lourde. Rejeté par le développeur. |
| **RPM / dnf** | Spécifique Fedora. Maintenance d'un dépôt COPR. Ne couvre pas les autres distributions. Rejeté par le développeur. |
| **Simple script shell + venv** | L'utilisateur doit installer Python, GTK, et les dépendances système. Pas de « double-clic et ça marche ». |
| **pip install depuis PyPI** | Même problème : l'utilisateur doit installer GTK4/libadwaita manuellement. PyPI ne gère pas les dépendances système. |
| **AppImage « légère » (sans GTK bundlé)** | L'utilisateur doit avoir GTK4 installé. L'AppImage n'est pas autonome. Contre le principe « télécharger et lancer ». |

---

### Conséquences

- **Développement inchangé :** le développeur continue à exécuter
  `python -m openrunner55` depuis le dépôt. L'AppImage n'interfère pas.
- **Script de build :** `scripts/build-appimage.sh` est maintenu avec le
  code source. Il est exécuté manuellement avant chaque release.
- **Pas de CI/CD :** le build AppImage est déclenché manuellement sur la
  machine du développeur (Fedora). Pas de GitHub Actions.
- **README.md :** documente les deux modes (développement avec prérequis
  système, et distribution via AppImage). Liste les dépendances système
  pour le mode développement (`dnf install python3-gobject gtk4 libadwaita`).
- **Taille estimée de l'AppImage :** 150-250 Mo (Python + GTK + libs).
  Acceptable pour un téléchargement ponctuel depuis GitHub Releases.

**Références :** ADR-002 pour la structure du package, ADR-003 pour le
choix GTK 4, ADR-004 pour secretstorage, ADR-006 pour pyudev.
