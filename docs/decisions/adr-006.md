## ADR-006 — Détection USB via pyudev + polling fallback

**Contexte :** L'exigence EF-10 impose la détection de la montre branchée en
USB avant tout transfert. L'exigence EF-20 demande la gestion de la
déconnexion USB en cours de transfert (interruption propre, notification).
La FR55 se monte en USB mass storage, le point de montage typique est
`/run/media/$USER/GARMIN`. Le montage automatique est géré par GNOME
(gvfs/udisks). L'utilisateur branche et débranche manuellement sa montre.

**Décision :** `pyudev` comme mécanisme principal de détection, avec un
polling du point de montage en fallback.

### Architecture du module `watch/detector.py`

```
┌─────────────────────────────────────────────────┐
│                  WatchDetector                  │
│                                                 │
│  ┌──────────────┐    ┌───────────────────────┐  │
│  │ pyudev       │    │ Polling (fallback)    │  │
│  │ Monitor      │    │ toutes les 1s         │  │
│  │ (événements  │    │ vérifie mount_path    │  │
│  │  add/remove  │    │ + GarminDevice.xml    │  │
│  │  block dev)  │    │                       │  │
│  └──────┬───────┘    └──────────┬────────────┘  │
│         │                       │               │
│         └───────────┬───────────┘               │
│                     ▼                           │
│         ┌──────────────────────┐                │
│         │ État interne         │                │
│         │ connected: bool      │                │
│         │ mount_path: Path|None│                │
│         └──────────┬───────────┘                │
│                    │                            │
│                    ▼                            │
│    signal: on_status_changed(connected: bool)   │
└─────────────────────────────────────────────────┘
```

Deux chemins de détection complémentaires :

1. **pyudev (actif) :** écoute les événements `bind`/`unbind` du sous-système
   `block` via `pyudev.Monitor`. Quand un device avec le label `GARMIN` est
   détecté, vérifie la présence de `GarminDevice.xml` pour confirmer qu'il
   s'agit bien d'une FR55. Signale immédiatement `connected=True` et le
   chemin de montage.

2. **Polling (passif, fallback) :** toutes les secondes, vérifie si
   `/run/media/$USER/GARMIN/GARMIN/GarminDevice.xml` existe. Si l'état
   change (monté ↔ démonté), émet le signal. Couvre le cas où pyudev ne
   reçoit pas l'événement (rare : permissions, conteneur, session non
   systemd).

Identification de la FR55 : vérification de la présence de
`GarminDevice.xml` dans le dossier `GARMIN/` à la racine du volume,
conformément à l'arborescence documentée dans `docs/exploration/tree-FR55.md`.

**Alternatives écartées :**

| Alternative | Raison du rejet |
|------------|-----------------|
| **Polling seul** | Latence de détection (1s), consommation CPU continue bien que négligeable. Ne détecte pas le débranchement « sale » (sans umount). |
| **`Gio.VolumeMonitor` (GLib)** | Intégré à la stack GTK/GLib, zéro dépendance externe. Mais : API GLib complexe, documentation rare, spécifique à GNOME/GVFS. pyudev est plus générique et mieux documenté. |
| **`watchdog` (inotify)** | Surveille l'arborescence de fichiers, pas le montage de volume. Ne détecte pas le montage initial, seulement les changements dans un dossier déjà monté. |
| **Fichier `/proc/mounts` polling** | Trop bas niveau, parsing fragile, ne détecte pas le type de device. |

**Conséquences :**

- **Dépendance `pyudev` :** paquet Python (`pyudev`) installable via pip.
  Utilise `libudev` sous-jacent (présent sur toute distribution Linux). Pas
  de dépendance système supplémentaire.
- **Thread séparé :** le `Monitor` pyudev et le polling tournent dans un
  thread dédié pour ne pas bloquer la boucle principale GTK. Le signal
  `on_status_changed` est émis thread-safe via `GLib.idle_add()`.
- **Débranchement en cours de transfert :** quand `connected` passe à
  `False` pendant une opération de sync, le service en cours annule
  proprement l'opération, journalise les fichiers déjà transférés, et notifie
  l'utilisateur (EF-20).
- **Permissions :** l'utilisateur standard a accès aux événements udev sur
  sa session. Pas de privilèges root requis.
- **Fallback polling conservé même si pyudev fonctionne :** le polling
  coûte un `os.path.exists()` par seconde — coût négligeable. Il sert de
  filet de sécurité si pyudev manque un événement.

**Références :** EF-10, EF-20. ADR-002 pour le module `watch/`.
