## ADR-005 — Persistance locale en SQLite (historique et logs)

**Contexte :** Les user stories US-4.2 et US-4.3 exigent un historique des
synchronisations et des logs d'opération persistants entre les redémarrages.
Les données sont structurées (date, sens, nombre de fichiers, statut) et
consultables depuis l'interface. Le volume de données est faible : quelques
dizaines de syncs par mois, quelques centaines de logs. L'exigence ENF-6
demande un module dédié au stockage.

**Décision :** Base SQLite via le module stdlib `sqlite3`. Fichier unique
`~/.config/openrunner55/openrunner.db`.

### Schéma

```sql
-- Historique des synchronisations
CREATE TABLE sync_history (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp  TEXT    NOT NULL DEFAULT (datetime('now')),
    direction  TEXT    NOT NULL CHECK (direction IN ('up', 'down', 'both')),
    file_count INTEGER NOT NULL DEFAULT 0,
    status     TEXT    NOT NULL CHECK (status IN ('success', 'partial', 'failed')),
    details    TEXT              -- JSON libre : liste des fichiers, erreurs
);

-- Logs d'opération
CREATE TABLE operation_logs (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TEXT    NOT NULL DEFAULT (datetime('now')),
    level     TEXT    NOT NULL DEFAULT 'INFO' CHECK (level IN ('DEBUG', 'INFO', 'WARN', 'ERROR')),
    message   TEXT    NOT NULL
);

-- Fichiers déjà transférés (déduplication)
CREATE TABLE transferred_files (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    file_name      TEXT    NOT NULL,
    file_hash      TEXT,              -- SHA256 du contenu (optionnel, MVP : NULL)
    direction      TEXT    NOT NULL CHECK (direction IN ('up', 'down')),
    source         TEXT    NOT NULL CHECK (source IN ('activity', 'monitor', 'sleep', 'metrics', 'workout')),
    transferred_at TEXT    NOT NULL DEFAULT (datetime('now')),
    gc_activity_id BIGINT             -- ID côté GC si applicable (upload)
);
```

### Module `store/`

- `database.py` — connexion, création des tables, migrations légères
- `history.py` — `log_sync(direction, file_count, status, details)`, `get_history(limit=50)`
- `logger.py` — `log(message, level)`, `get_logs(limit=100)`, filtre anti-credentials
- `transfers.py` — `is_already_transferred(file_name, direction, source) -> bool`, `mark_transferred(file_name, direction, source, gc_activity_id=None)`

**Alternatives écartées :**

| Alternative | Raison du rejet |
|------------|-----------------|
| **JSON plat** | Pas de requêtage structuré (filtre par date, statut). Risque de corruption sur écriture concurrente. À réimplémenter manuellement. |
| **CSV** | Pas de typage, parsing fragile, pas de mise à jour partielle. Ne répond pas à US-4.2. |
| **Peewee / SQLAlchemy** | ORM overkill pour 3 tables et quelques requêtes simples. Ajoutent des dépendances et de la complexité. |
| **Fichier de log texte brut** | Non structuré, impossible à requêter, doublon avec le module `logging` standard de Python. |
| **JSON Lines (.jsonl)** | Meilleur que JSON plat (append-only), mais toujours pas de requêtage. Acceptable en fallback si SQLite pose problème. |

**Conséquences :**

- **Zéro dépendance externe :** `sqlite3` est dans la bibliothèque standard
  Python. Aucun pip install supplémentaire.
- **Fichier unique :** `openrunner.db` dans `~/.config/openrunner55/`.
  Facile à sauvegarder ou supprimer pour repartir à zéro.
- **Pas de concurrence :** application mono-utilisateur, mono-processus. Pas
  besoin de WAL, de locking avancé ou de pool de connexions.
- **Migrations légères :** une table `schema_version` dans la base pour
  versionner le schéma. `database.py` applique les migrations au démarrage
  si nécessaire (ALTER TABLE, nouvelles colonnes).
- **Sécurité :** le module `store/logger.py` intègre un filtre qui masque
  les patterns d'email avant insertion (conformité ENF-4). Aucun credential
  ne passe dans les logs persistés.
- **Déduplication :** la table `transferred_files` permet d'éviter les
  re-uploads et re-downloads en consultant l'historique local. Plus fiable
  que la comparaison de timestamps via `get_activities()` de GC (limité à
  20 résultats par page). La colonne `file_hash` (SHA256) est prévue mais
  non calculée dans le MVP — la déduplication se fait sur `(file_name,
  direction, source)`.
- **Taille prévisible :** < 1 Mo pour des années d'utilisation.

**Références :** EF-17, EF-18, ENF-4, US-4.2, US-4.3. ADR-002 pour le module `store/`.
